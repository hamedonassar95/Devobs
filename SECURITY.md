# Security Policy

## Supported Versions

This project currently supports the latest version available on the `main` branch.

| Version | Supported |
| --- | --- |
| `main` | ✅ |
| Older commits or branches | ❌ |

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub Issues.

Use GitHub's **Private Vulnerability Reporting** feature for this repository:

1. Open the repository's **Security** section.
2. Open **Advisories**.
3. Select **Report a vulnerability**.
4. Provide as much technical detail as possible.

Please include:

- A clear description of the vulnerability.
- The affected file, workflow, or component.
- Steps to reproduce the issue.
- The potential security impact.
- Relevant logs, screenshots, or proof of concept when appropriate.
- Any suggested mitigation or fix, if known.

## Sensitive Information

Do not include real passwords, API keys, access tokens, private keys, credentials, or other secrets in reports, commits, pull requests, or public issues.

If a credential has already been exposed, revoke or rotate it immediately before continuing the investigation.

## Scope

Security reports related to the following are welcome:

- GitHub Actions workflows
- CI/CD configuration
- GitHub Pages deployment
- Python scripts
- Repository configuration
- Dependency and supply-chain security
- Secret exposure
- Access-control or branch-protection issues

## Responsible Disclosure

Please allow reasonable time to investigate and remediate a confirmed vulnerability before publicly disclosing technical details.
