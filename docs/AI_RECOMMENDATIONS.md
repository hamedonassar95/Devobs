# توصيات AI-4 المحلية من runbooks

**الحالة: تجربة محلية، اقتراح فقط.** يربط هذا الجزء فرضيات AI-3 المحدودة بإرشادات ثابتة داخل الشيفرة. لا يشخّص السبب الجذري ولا ينفّذ أوامر أو تغييرات.

## طريقة العمل

1. يقرأ التقرير سجل JSONL المحلي الذي أنتجه AI-1.
2. يستخدم AI-3 لتجميع السجلات وإنتاج إشارات `POSSIBLE`.
3. يطابق المحرك معرّفات الإشارات المعروفة فقط (`timeout`, `connection`, `dns`, `permission`, `dependency`, `memory`) مع فحوص قراءة فقط واقتراح تغيير محتمل.
4. تُعرض الإشارات المجهولة كعدد غير مربوط، بلا تخمين إصلاح لها. أي اقتراح يحتاج مراجعة بشرية وموافقة مستقلة قبل تطبيقه.

من جذر المستودع:

```sh
node scripts/ai_intelligence/recommendation_report.mjs --store <local-jsonl-file>
node --test tests/ai_recommendations.test.mjs
```

الأمر الأول يقرأ السجل ولا يكتب فيه؛ ويعيد ترتيب عرض ثابتًا، لا ترتيبًا حسب الخطورة أو احتمال صحة السبب. المخرجات لا تتضمن نصوص السجل الخام. لا تستخدم سجلات حقيقية حتى تُعتمد الخصوصية والاحتفاظ والحذف والموافقة.

يستخدم فحص الاختبار مشغّل Node المدمج عبر `node --test`؛ راجع [توثيق Node.js الرسمي لمشغّل الاختبارات](https://nodejs.org/api/test.html).

## حدود الدليل

- `POSSIBLE` و`heuristic_signal` موروثان من قواعد AI-3، وليسا احتمالًا معايرًا أو إثباتًا. الإرشادات عامة ولم تُتحقق على حادث حقيقي.
- لا يوجد تنفيذ تلقائي، أو اتصال شبكة، أو LLM، أو فتح PR، أو تغيير إعداد. الحقل `automatic_execution: false` جزء من المخرجات.
- `UNKNOWN` أو غياب الاقتراح يعني عدم وجود قاعدة محلية مطابقة، وليس أن النظام سليم.
- الاختبارات اصطناعية؛ لا تثبت ملاءمة الإرشادات لبيئة تشغيل بعينها.

تدعم ممارسات NIST توثيق القياس وعدم اليقين والاختبار، وتوضيح أدوار البشر عند الإشراف على أنظمة الذكاء الاصطناعي؛ ذكرها هنا مرجع تصميمي فقط وليس ادعاء امتثال: [NIST AI RMF 1.0](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-1.pdf) و[Human-AI Interaction](https://airc.nist.gov/airmf-resources/airmf/appendices/app-c-ai-risk-management-and-human-ai-interaction/).
