- شجرة الملفات متداخلة بدرجة كبيرة: 72 ملفًا مشتركًا، مع أربعة اختلافات في الملفات المشتركة (`scripts/repository_dispatch.mjs` و`server.ts` و`src/components/github/GitHubTab.tsx` واختبار dispatch). نسخة `ops` تشمل 36 ملفًا إضافيًا، معظمها مهارات تشغيلية؛ ونسخة AI Intelligence لها `package-lock.json` إضافي. لذلك عومل المستودعان كمصدرين متقاربين، لا كمنتجين مستقلين يحتوي كل منهما مجموعة ميزات منفصلة.
- رخصة مستودع `ops` هي MIT. لم تُنسخ ملفات المصدر؛ استُخدم نمط مهمة المتابعة كمرجع، وأُعيد تنفيذ الجزء المناسب عبر Google Tasks API الرسمية.

## ما يفيد Devobs وما تقرر بشأنه

| القدرة في المصدر | ما ثبت من الملفات | القرار في Devobs |
| --- | --- | --- |
| Google Docs وSheets وSlides وCalendar وChat | خدمات وواجهات Workspace موجودة في المصدر. | تغطية AI-7 الاختيارية موجودة بالفعل في Devobs بإضافات سابقة؛ لم تُنقل النسخ الواسعة. |
| Google Tasks | `googleTasksService.ts` ينشئ مهامًا من حادثة، لكن الملاحظات تتضمن وصف الحادثة ووقت رصدها وتتبعها وتحليلها، وينشئ ثلاث مهام. | إضافة متابعة واحدة بمحتوى ثابت وأعداد AI-7 فقط، إلى القائمة الافتراضية وبعد المعاينة والتأكيد. لا قراءة للقوائم أو المهام ولا تعديل أو حذف. صلاحية `tasks` نفسها واسعة؛ الميزة المحلية ترسل طلب إدراج واحدًا. |
| Google Forms | الخدمة تعرض النماذج ونتائج الردود، وتنشئ النماذج وتحذفها. | لم تُنقل: قراءة ردود العملاء والحذف ليسا مطلوبين لتشغيل AI-7. يمكن دراسة نموذج استقبال خدمة لاحقًا بتحديد بياناته ومدة الاحتفاظ به أولًا. |
| Gmail وDrive | المصدر يقرأ ويرسل البريد، ويسرد ملفات Drive ويرفعها ويحذفها. | لم تُنقل إدارة البريد أو الملفات الواسعة. Devobs لديه تصدير ملفات جديدة بنطاق `drive.file`؛ لا حاجة لقراءة بريد أو ملفات المستخدم. |
| Google Keep | `KeepTab.tsx` يحفظ ملاحظات تجريبية في `localStorage` ويحتوي بيانات ابتدائية؛ لا يظهر موصل Google Keep API. | لم تُنقل كتكامل سحابي، لأنها واجهة ملاحظات محلية وليست خدمة Keep موصولة. |
| Firebase Firestore | `firebaseFirestore.ts` يقرأ ويكتب ويحذف خوادم وحوادث ونشرات في Firestore. | لم تُنقل قاعدة بيانات موازية أو إعدادات Firebase؛ Devobs يملك مسار بيانات وحدود مستأجرين خاصة به. |
| إعادة تشغيل الخوادم ووضع الصيانة | `handleRestartServer` يغيّر الحالة والأرقام في الواجهة، ثم يكتب الحالة في Firestore وينشئ حادثة نجاح اصطناعية. لم يظهر اتصال بخادم أو وكيل تشغيل. | لم تُنقل باعتبارها أتمتة حقيقية؛ عرضها كتشغيل فعلي سيكون مضللًا وخطرًا. |
| نشر hotfix مباشرة من اللوحة | نسخة `ops` تحتوي مسارًا يقبل GitHub PAT ويبني أوامر `git push`، مع خيار force push؛ نسخة DevObs AI Intelligence أزالت المسار والواجهة. | استُبعد بالكامل. Devobs يستخدم مراجعة GitHub وCI ومسار الدمج المعتمد بدل أخذ رمز PAT من مستخدم اللوحة. |
| GitHub Actions dispatch | المصدر يرسل نتيجة CI كبيانات بناء وصفية إلى Devobs عند نجاح الدفع إلى main، ويتطلب إعداد secret يدويًا. | يوجد في Devobs مستقبل dispatch محدود مسبقًا؛ لا تنقل بيانات الحوادث ولا تتجاوز بوابات CI. |

## حدود ميزة Tasks الجديدة

- لا تنشئ مهمة إلا بعد تأكيد صريح، وتتضمن المعاينة عنوانًا ثابتًا وأعدادًا مسموحة وتاريخ استحقاق يختاره المستخدم.
- وجهة الطلب ثابتة: قائمة Google Tasks الافتراضية. لا يقبل معرف قائمة حرًا ولا ينفذ `GET` أو `PATCH` أو `DELETE`.
- لا يُرسل نص حادثة أو سجل أو اسم عميل أو عنوان خادم. رمز OAuth قصير العمر يبقى في ذاكرة الصفحة ولا يُخزن.
- الميزة محلية ومعطلة دون OAuth Client ID اختياري. لم يُربط حساب Google ولم تُنشأ مهمة حقيقية؛ اختبارات Google تستخدم استجابات وهمية.
- إذا كانت نتيجة الطلب الشبكي غير مؤكدة، يجب فحص Google Tasks قبل إعادة المحاولة حتى لا تنشأ مهمة مكررة.
