# قائمة التحقق للمزامنة الأولية

هذه خطوات مستقبلية للمراجعة؛ لم تُنفّذ مزامنة في إطار هذا التغيير.

## قبل الاتصال

1. افتح إعداد Git Sync في GitBook، وتحقق يدويًا من المستودع والفرع ومجلد المشروع المرتبطين حاليًا. لا تفترض أن حالة التكامل أو اسم المساحة يثبت وجهة Git.
2. عند الحاجة إلى إعادة تفويض GitHub، اطلب من مالك الحساب إكمالها من واجهة GitBook/GitHub، مع حصر التطبيق في مستودع `hamedonassar95/Devobs` فقط. لا تمنح وصولًا إلى جميع المستودعات لهذا التحضير.
3. تأكد أن سياسة نشر مساحة GitBook مناسبة للمحتوى المراد إظهاره. إبقاء المساحة خاصة لا يجعل ملفات GitHub المرفوعة خاصة؛ المستودع عام.
4. راجع قائمة الملفات في الفرع؛ يجب أن تقتصر على `docs/gitbook-sync-prep/` وأن تخلو من أي مصدر خاص أو سر.

## إعداد تجربة محدودة

1. اختر المستودع `hamedonassar95/Devobs` والفرع `docs/gitbook-sync-prep`.
2. عيّن مجلد المشروع إلى `docs/gitbook-sync-prep/`، حيث توجد `.gitbook.yaml` و`README.md` و`SUMMARY.md`.
3. اختر اتجاه البداية **GitHub → GitBook** لهذه التجربة. لا تستخدم **GitBook → GitHub** لمساحة تحتوي صفحات خاصة قبل مراجعتها واعتماد نشرها صراحةً.
4. اعرض المعاينة وتحقق من أن الفهرس يعرض صفحات هذا المجلد وحده، وأن الروابط تعمل، ولا تظهر صفحات المستودع أو مساحة أخرى.
5. راجع سجل التغيير والملفات الناتجة قبل اعتماد أي مزامنة مستمرة. أوقف التجربة عند اختلاف المجلد أو الفرع أو ظهور ملف غير متوقع.

## بوابة الموافقة

لا تفعّل الربط أو تبدأ المزامنة أو النشر من هذه الوثيقة. قبل ذلك، يجب على مالك الحساب مراجعة وجهة Git Sync ومجلد المشروع واتجاه المزامنة وخصوصية الموقع. يجب أن يثبت تشغيل اختباري فعلي نجاح المزامنة قبل وصف التكامل بأنه نشط.
