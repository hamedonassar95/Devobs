# KI-2 — محرك إدخال المعرفة المحلي

**الحالة:** نموذج أولي محلي اصطناعي، على فرع مراجعة KI-2. لا يُعد خدمة تشغيلية أو جاهزية إنتاج.
**الأساس:** KI-0 وKI-1 مدمجان في `main` عبر PR #787 وPR #788؛ أساس هذا العمل `442012702a60ebf1bb1df43c4aa9e08fb94cab03`.

## الغرض وحدود التنفيذ

يحوّل `scripts/knowledge_ingestion.py` مستندًا نصيًا اصطناعيًا محددًا يدويًا إلى مانيفست KI-1 صالح. يعتمد على مكتبات Python القياسية، ويعيد بيانات وصفية منظمة إلى stdout في وضع `dry_run` افتراضي. لا يكتب المستند أو المانيفست إلى القرص، ولا يرسل محتوى إلى شبكة، ولا يقرأ إلا ملفات محلية يحددها المستخدم صراحةً. حالة التكرار والإصدارات والحذف موجودة في ذاكرة العملية فقط.

المدخلات: سجل سياسة KI-0 داخل طلب JSON، وملف UTF-8 نصي يصرح بأن نوع مصدره `synthetic_fixture`، ومفتاح مستند وإصدار مصدر ونوع محتوى ووقت إنشاء وإعداد تقسيم. تُرفض الحقول الإضافية، ومفاتيح JSON المكررة، والروابط الشبكية أو أي تنسيق خارج أنواع KI-1 النصية المدعومة. لا يُفسّر المحتوى ولا يُنفّذ. هذا التصريح لا يثبت منشأ البايتات؛ لذا يجب ألا يمرر المشغل بيانات خاصة أو حقيقية لهذا النموذج المحلي.

## التكامل مع KI-0 وKI-1

- يستدعي `validate_policy` من KI-0 دون تكرار قواعد الموافقة أو الاحتفاظ. يلزم أن يكون نوع المصدر `synthetic_fixture`، وأن تتطابق سياسة المصدر والإصدار والمستأجر والمستودع. حالات الموافقة المعلنة لا تثبت هوية أو تفويضًا حقيقيًا؛ التقرير يضع `authorization_assurance: STRUCTURE_ONLY`.
- يستخدم `deterministic_id` و`canonical_manifest_bytes` و`validate_manifest` من KI-1. لا يوجد محلل سياسة أو مانيفست موازٍ.
- سياسة KI-0 في KI-1 v1 تربط بصمة محتوى المصدر بالإصدار الجذري. تُراجع البايتات الحالية في الذاكرة، ثم يُتحقق من المانيفست الكامل قبل إرجاع أي نجاح. الإصدار اللاحق يستخدم SHA-256 مختلفًا وسلسلة خطية مع `previous_version_id`؛ إعادة البصمة نفسها تعيد عملية `DUPLICATE` دون إضافة نسخة.
- يقتصر KI-1 v1 على مستند منطقي واحد لكل مصدر. هوية المستند يحددها `document_key` ضمن نطاق المستأجر والمستودع والمصدر؛ ولا يوجد دمج تكرارات عابر للمستأجرين.

## حدود الموارد والتقسيم

| الحد | القيمة في KI-2 | السبب |
| --- | ---: | --- |
| حجم طلب JSON | 32 KiB | حد صريح قبل التحليل |
| حجم المستند | 65,536 بايت | يطابق الحد الأقصى في مخطط KI-1 v1 |
| حجم هدف المقطع | 1,024 بايت افتراضيًا؛ 4 إلى 16,384 | حدود بايت قابلة للتحقق |
| التداخل | صفر فقط | KI-1 v1 يرفض تداخل النطاقات |
| عدد المقاطع | 2,048 كحد للمحرك | حد أدنى من حدود KI-1 والطلب |
| عدد إصدارات المستند | حد KI-1 البالغ 500 | التحقق النهائي من KI-1 |
| حجم المانيفست | حد KI-1 البالغ 1 MiB | التحقق قبل الإرجاع |
| عدد المستندات في حالة محرك واحد | 100 | حد حالة الذاكرة؛ مصدر واحد لكل مستند |
| أحجام benchmark / التكرارات | 4 أحجام مميزة / 20 تكرارًا لكل حجم كحد أقصى | يمنع طلب قياس غير محدود |

تُحفظ البايتات الأصلية كما قُرئت ويُرفض UTF-8 غير الصالح؛ لا يوجد تطبيع Unicode. التقسيم ينتج فواصل نصف مفتوحة `[start_offset, end_offset)` بوحدة `UTF8_BYTE`، ويحرّك النهاية إلى حدّ نقطة Unicode صالح عند الحاجة. كل مقطع متصل وغير متداخل، وتغطي المقاطع كامل البايتات. تُحسب SHA-256 من البايتات الأصلية ومن كل شريحة مقطع، ثم يتحقق KI-1 من المانيفست.

لا تدعم هذه المرحلة PDF أو DOCX أو HTML أو الأرشيفات أو الصور أو الصيغ التنفيذية. ولا تدعم التداخل لأن عقد KI-1 الحالي يمنعه. رفع هذه القيود يتطلب تغييرًا ومراجعة منفصلين لعقد KI-1، وليس التفافًا حوله في المحرك.

## الاستخدام المحلي

```sh
python3 scripts/knowledge_ingestion.py ingest \
  --request tests/fixtures/knowledge/ingestion-valid.json \
  --document tests/fixtures/knowledge/synthetic-document.txt
```

يُرجع الأمر JSON يحتوي `decision`, `manifest` و`report`. لا يتضمن manifest نص المستند. يتحقق KI-1 أولًا من المانيفست المؤقت مع البايتات الموجودة في الذاكرة؛ ثم يُتحقق من النسخة الوصفية التي تُعاد دون النص. لذلك يبين التقرير `input_content_verification: VERIFIED_IN_MEMORY` و`manifest_validation.content_integrity: UNVERIFIED_NO_CONTENT_BYTES` مع `assurance: STRUCTURE_ONLY` للنسخة المعادة. لتجربة سجل إصدارات اصطناعي، يمكن تمرير `--history` مع مانيفست KI-1 محلي صريح؛ التاريخ يحتفظ ببيانات وصفية لا بالمحتوى. الأخطاء تُرجع رمزًا ثابتًا ولا تطبع محتوى المدخل. أي فشل في السياسة أو تحقق KI-1 يجعل العملية كلها `FAIL` ولا يعيد مانيفستًا جزئيًا ناجحًا.

```sh
python3 scripts/knowledge_ingestion.py benchmark --repetitions 5
```

الـbenchmark يدوي ومحدود ويستخدم بايتات اصطناعية ثابتة. يقيس زمن خط المعالجة، وسيط التحقق من المانيفست، عدد المقاطع، وأعلى تخصيص Python مرصود باستخدام `tracemalloc`. لا توجد حدود أداء في الاختبارات ولا تُدّعى زيادة سرعة.

## التكرار وإدارة دورة الحياة

داخل كائن المحرك الواحد، تكرار الطلب نفسه حتمي ويمثل `DUPLICATE`. تغيير البايتات يضيف إصدارًا جديدًا بمعرّف حتمي ويربطه بالإصدار السابق، بشرط وقت أحدث وسلسلة خطية صحيحة. `delete_document` و`revoke_source` يمنعان القراءة وإعادة الإدخال في ذاكرة المحرك. يقبل استرجاع التاريخ مانيفستًا محليًا صريحًا بعد تحقق KI-1، ويستعيد بيانات وصفية فقط.

هذه دورة حياة تجريبية متطايرة: لا يوجد تخزين دائم، أو تحكم تنافسي، أو تزامن بين العمليات، أو حذف فعلي آمن، أو إزالة من النسخ الاحتياطية/الفهارس الموزعة. لا يُثبت هذا النموذج تنفيذ سياسة الاحتفاظ أو التفويض.

## نموذج التهديد والخصوصية

- كل السياسة والملفات والمحتوى غير موثوقة؛ محتوى الوثيقة بيانات خاملة ولا يستطيع منح صلاحيات أو تغيير سياسة النظام أو السماح بإجراء وكيل.
- لا شبكة أو URL resolution أو embeddings أو قاعدة بيانات أو استدعاء Agent أو ملفات العملاء أو سجلات الإنتاج.
- لا تُطبع نصوص المستندات في التقارير أو الأخطاء. تُخرج المانيفست بصمات ومواقع بايتات وبيانات نطاق فقط.
- قبول سياسة معلنة يثبت اتساق البنية في الاختبار المحلي فقط؛ لا يثبت مصادقة المستأجر أو صلاحية المالك أو الموافقة الحقيقية أو عزل وقت التشغيل.
- الحذف والإلغاء مؤقتان داخل الذاكرة ولا يثبتان المحو الدائم. يلزم KI-3 وما بعده تصميم تخزين ومراجعة هوية وعزل واحتفاظ وحذف وتدقيق مستقلة.

لا يغير KI-2 بوابات P01 (**BLOCKED / NO-GO**) أو AI-9 (**BLOCKED**) أو Codex runtime (**OPEN**). لا يُنشئ خدمة API ولا يفعّل staging أو إعداد إنتاج.

## التحقق والتراجع

شغّل اختبارات المحرك وKI-1 وKI-0 من جذر المستودع. التراجع هو عكس التغيير المعزول لهذه المرحلة؛ لا توجد كتابة محتوى دائمة أو بنية تحتية لإزالتها. احتفظ بعقود KI-0/KI-1 والبيانات الاصطناعية التي تحتاجها الاختبارات السابقة.

## شروط KI-3

الخطوة التالية المقترحة هي **KI-3: خط استرجاع معجمي ومجموعة تقييم اصطناعية ثابتة**. قبلها: مراجعة/دمج KI-2، تجميد دلالة الإصدارات وحد KI-1، وتحديد fixtures واستشهادات دقيقة واختبارات عزل سلبية. لا يُسمح ببيانات حقيقية أو تخزين دائم أو نموذج أو شبكة قبل مراجعة منفصلة للحقوق والهوية والخصوصية والاحتفاظ والحذف وموافقة الإنسان.
