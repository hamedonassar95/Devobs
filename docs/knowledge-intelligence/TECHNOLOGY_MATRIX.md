## Comparison conclusions

1. Start with a local synthetic evaluation of pgvector because the repository
   already contains PostgreSQL contracts and RLS work. This is a test candidate,
   not approval to alter an existing database.
2. Compare Qdrant only if measured workload or operational isolation requirements
   justify a second service.
3. Use Chroma or FAISS only for a bounded disposable prototype if they make
   local evaluation easier; neither removes Devobs' tenant authorization and
   durable deletion responsibilities.
4. Sentence Transformers may be evaluated later, after multilingual relevance,
   package integrity, offline model distribution, CPU/RAM and model-license
   requirements are recorded.
5. Reuse OpenTelemetry, Prometheus and Grafana already present. Add MLflow only
   if an explicit experiment/version lineage requirement is not met by the
   current deterministic report artifacts.

No generic CPU/RAM number or hosted monthly quote is defensible without a corpus,
model, concurrency, retention, region, backup and availability target. The
[cost model](COST_MODEL.md) explains the sizing formula and the evidence needed.
