# استراتيجية اختيار نماذج الذكاء الاصطناعي في Devobs

## الغرض

تسجل هذه الوثيقة النماذج المرشحة بحسب نوع العمل، وتفصل بين **التوصية** وبين
**الإعداد الفعلي في المستودع**. إدراج اسم نموذج هنا لا يفعّله ولا يمنحه صلاحية
على المستودع أو بيئة النشر.

الإعداد الفعلي أدناه مستخرج من ملفات سير العمل في المستودع. تتغير إصدارات
النماذج ومعرّفاتها وتوفّرها وحصصها؛ لذلك تحقق من المعرّف لدى المزوّد ومن دعم
إصدار gh-aw المستخدم قبل أي تفعيل.

## الإعداد الفعلي في Devobs

بحسب ملفات سير العمل الحالية:

- المحقق الأساسي يستخدم GitHub Copilot مع النموذج gpt-4.1 في
  .github/workflows/incident-investigator.md.
- مولّد patch يستخدم GitHub Copilot مع النموذج gpt-4.1 في
  .github/workflows/phase8b-ai-patch-generator.md.
- يوجد مسار احتياطي يدوي عبر Vertex AI مع Gemini 2.5 Pro في
  .github/workflows/incident-investigator-vertex.md. يحتاج هذا المسار إعداد
  Google Cloud Workload Identity Federation ومتغيرات المستودع الموضحة في
  docs/VERTEX_AI_FALLBACK.md.
- توجد تجربة احتياطية يدوية عبر Claude في
  .github/workflows/incident-investigator-claude.md. تستخدم محرك Claude والاسم
  المنطقي `sonnet-6x` وتتطلب سر المستودع `ANTHROPIC_API_KEY`. لا تعمل تلقائيًا
  عند فشل Copilot، ولا تغيّر المحقق الأساسي.
- مراجعة ادعاءات iOS تبدأ بفرز محلي حتمي عبر `scripts/ios_claim_triage.py`؛
  ويحوّل `scripts/ios_claim_ai_handoff.py` الحقول المسموح بها إلى تعليمات
  عربية للمراجعة. هذا المسار لا يستدعي نموذجًا ولا يرسل بيانات تلقائيًا؛
  ينسخ المراجع التعليمات يدويًا إلى أداة ذكاء اصطناعي معتمدة.

الاسم `sonnet-6x` alias يديره gh-aw وليس تثبيتًا لمعرّف Claude 3.5 Sonnet بعينه.
لذلك لا تضمن التجربة تشغيل إصدار 3.5: تحقّق من النموذج الفعلي والتوافر والحصة
والتكلفة لدى Anthropic قبل أول تشغيل يدوي. خزّن المفتاح في GitHub Actions Secrets؛
لا تضع قيمته في ملف أو سجل.

هذه التفاصيل تصف الإعداد الموجود في ملفات المستودع، ولا توصي باستبدال النماذج أو
تثبت التوافر الحالي لدى المزوّد. افحص سجلات التشغيل وإعداد حساب المزوّد قبل
الاعتماد على نموذج أو alias.

تثبت أن مسارات Vertex أو Claude متاحة أو مهيأة.

لا تستبدل هذه الإعدادات تلقائيًا. يتطلب تغيير نموذج إنتاجي تحديث محرك
المصادقة واسم النموذج في ملف المصدر، ثم إعادة توليد
ملف lock وتشغيل CI والتحقق من المسار الاحتياطي.

## ضوابط الدمج

قبل اعتماد أي نموذج مرشح:

1. تحقق من توافر معرّف النموذج في حساب المزوّد والمنطقة، ومن دعم إصدار gh-aw
   الحالي له. لا تعتمد على اسم تسويقي أو alias وحده.
2. راجع المصادقة والحصص وحدود الطلبات والتكلفة وشروط الاحتفاظ بالبيانات.
   استخدم OIDC أو أسرارًا قصيرة الصلاحية عند دعم المزوّد، ولا تضع المفاتيح في
   الملفات أو السجلات.
3. اختبر النماذج على مجموعة حالات غير إنتاجية ذات نتائج مرجعية، تشمل حالات
   نجاح وفشل وأدلة ناقصة. قارن دقة الاستشهاد بالأدلة، والادعاءات غير المسندة،
   وجودة الاختبار المقترح، وزمن الاستجابة، والتكلفة، وأخطاء 429.
4. ابدأ بتشغيل تجريبي محدود الصلاحيات. تبقى صلاحيات الأدوات منفصلة عن النموذج:
   التحقيق للقراءة، والتعليق عبر safe outputs فقط، ولا تنفيذ لنشر أو rollback.
5. لا تعتمد النموذج إلا بعد مراجعة بشرية للنتائج وخطة رجوع إلى النموذج السابق.

## قاعدة السلامة

النموذج يقدّم تحليلًا أو patch مقترحًا؛ لا تمنحه ثقة تشغيلية بسبب اسمه أو
نتيجة تقييم منفردة. يبقى قرار الدمج والنشر والاسترداد بيد الإنسان، وتظل
الحواجز البرمجية والصلاحيات الدنيا مطلوبة مهما كان النموذج المختار.
