# إعداد AI DevKit للمساهمين

يضيف هذا المستودع إعدادًا مشتركًا لـCodex وClaude Code، ومهارات لمراحل تطوير البرمجيات، ووثائق دورة العمل. ملفات المهارات موجودة محليًا في المستودع حتى تعمل بعد استنساخه دون اعتماد على مسار جهاز المساهم الذي أنشأها. مصدر النسخ ورخصتها موضحان في `THIRD_PARTY_NOTICES.md`.

## الاستخدام

1. افتح المستودع في Codex أو Claude Code؛ يستطيع الوكيل قراءة المهارات من مجلده.
2. اطلب المهارة باسمها عند الحاجة، مثل `dev-review` لمراجعة تغيير أو `structured-debug` لتتبع عطل.
3. ابدأ من `docs/AUTOMATION_HUB.md` عند استخدام وحدات CI/CD المشتركة؛ إعداد AI DevKit لا يشغّلها ولا يستبدلها.

## فحص الإعداد

يتطلب فحص الإعداد Node.js وnpm واتصالًا لتنزيل CLI:

```bash
npx --yes ai-devkit@0.70.1 lint
npx --yes ai-devkit@0.70.1 lint --feature ai-devkit-setup
```

## تحديث المهارات

المجلدان `.agents/skills/` و`.claude/skills/` نسخ متتبعة في Git. عند تحديث مهارة من سجل AI DevKit، راجع `.ai-devkit.json` ثم شغّل `npx --yes ai-devkit@0.70.1 install --overwrite` لتحديث النسخ. افحص الفرق يدويًا قبل الالتزام؛ لا تعتمد تحديثًا واسعًا غير مراجع.

مهارة `task` اختيارية، لكن CLI الإصدار `0.70.1` لا يوفر أمر `task`؛ يواصل سير العمل من دون تسجيل تقدم دائم حتى يتوفر الأمر في إصدار لاحق.

يحفظ كاشف استئناف دورة العمل مراجعة المتطلبات والتصميم، وإنشاء الخطة الأولية بعد المراجعتين، وتقدم المراحل 7–9 في قائمة داخل مستند التنفيذ الخاص بالميزة. علّم المرحلة كمكتملة بعد نجاح مراجعتها أو التحقق منها، وأعدها والمراحل اللاحقة إلى غير مكتملة عندما تتغير أدلتها. يتوقف الكاشف إذا غابت وثيقة مطلوبة بدل اقتراح مرحلة تتجاوزها، ويطابق مجلد المرحلة داخل مسار `paths.docs` حتى يحترم المجلدات المخصصة التي يحتوي اسمها على اسم مرحلة.

يجهز `dev-worktree` مجلد `.worktrees/` في ملف Git المحلي `info/exclude`؛ بذلك لا يضيف خطوة الإعداد تغييرًا غير ملتزم به إلى المستودع الأساسي.

مهارة `structured-debug` في Claude Code متاحة للاستدعاء اليدوي فقط، حتى لا يلتقطها تلقائيًا سير عمل تقارير الحوادث الذي يقرأ `.claude/skills`. هذا الإعداد يستخدم خيار Claude Code الموثق [`disable-model-invocation`](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill)؛ يستطيع Codex استدعاء نسخة المهارة تلقائيًا عند الحاجة. أعد هذا الإعداد بعد تحديث المهارات إذا استبدل التثبيت الملف المخصص. تستخدم اقتراحات حفظ الذاكرة نطاق `repo:<owner>/<repo>` لتجنب خلط معرفة المشاريع المختلفة.

## اعتماد سير العمل في مستودع آخر

انسخ [`templates/ai-devkit.json`](../templates/ai-devkit.json) إلى جذر المستودع الجديد، ثم شغّل الأمر التالي من داخله. يحدد القالب مصدر سجل المهارات صراحةً. يستخدم `init --template` الحقل `skill` لعناصر المهارات وفق [مرجع القالب الرسمي](https://ai-devkit.com/docs/9-agent-setup/#template-field-reference)؛ بعد التهيئة يحفظ CLI الاسم في `.ai-devkit.json` بالحقل `name`. سينشئ الإعداد والوثائق والمهارات المحلية للبيئتين المحددتين في القالب. يشير عنوان Git إلى الفرع الافتراضي المتغير للمصدر، لذلك راجع نسخ المهارات الناتجة قبل الالتزام بها:

```bash
npx --yes ai-devkit@0.70.1 init --template ./ai-devkit.json
```

هذا ينسخ إطار عمل تطوير البرمجيات إلى المستودع الجديد؛ أما وحدات CI المشتركة فتُستدعى من [مركز الأتمتة](AUTOMATION_HUB.md) باستخدام `workflow_call`، ولا تُنسخ شيفرتها بين المستودعات.

## الحدود

هذا تكامل لمساعدة المطور أثناء العمل، وليس وكيل نشر ذاتي. لا يضيف مفاتيح AI أو أسرارًا، ولا يرسل رسائل خارجية، ولا يدمج التغييرات أو ينشرها دون قرار ومراجعة من صاحب المشروع.
