# Free offline integration acceptance across the project namespaces

**VERIFIED local synthetic conversion/store behavior, not live connections.**
One command combines three existing open-source formats for each of the seven
approved namespaces and checks the real local event store and AI-7 snapshot.
No account, key, server, listener, deployment, model or paid resource is needed.

```sh
node scripts/portfolio_integration_acceptance.mjs
node --test tests/portfolio_integration_acceptance.test.mjs
```

Use Node.js 24 from the repository root. The CLI accepts **no arguments** and
reads only the three fixed public synthetic files under `examples/integrations/`.
It writes one aggregate JSON report after all checks and temporary-file cleanup
succeed. Errors return exit 2 with a fixed category and no partial report.
The library's validated fixture-text input supports local verification; neither
interface authenticates senders or grants project access.

## What is actually exercised

| Existing adapter | Per namespace | All seven |
| --- | ---: | ---: |
| [CloudEvents CI](CLOUDEVENTS_CI_BRIDGE.md) | One namespace-specific CI row | 7 |
| [Alertmanager v4](ALERTMANAGER_BRIDGE.md) | Two incidents | 14 |
| [Grafana OSS v1](GRAFANA_WEBHOOK_BRIDGE.md) | Two incidents | 14 |
| First import into separate disposable stores | 5 accepted, 0 duplicates | 35 accepted |
| Reverse-provider-order replay | 0 accepted, 5 duplicates | 35 duplicates ignored |

The namespaces are Devobs, devobs-saas, phone-repair-assistant-v2, al-dala-mobile,
LiveOps-Integration, DevObs-ai-Intelligence- and CineForge-AI. Each receives only
its own CI row and its explicitly bound monitoring events. Provider and project
event IDs must be disjoint, and actual stored IDs must match the selected inputs.
This is local fixture separation, **not hosted tenant isolation** or proof of
installation in another repository. The [OTLP bridge](OTLP_ERROR_RATE_BRIDGE.md)
keeps its existing Devobs-only scope; this command does not broaden it.

These fixtures contain no logs or metrics: each snapshot correctly reports four
incoming incident records, zero log clusters, zero anomaly candidates, zero
forecasts and zero recommendations. AI-7's `incidents` array represents log
clusters, not every input incident record. Stage counts are `[5,0,0,0,0,0,1]`;
empty-stage statuses are expected and do not establish detector quality.
The varying synthetic CI outcomes and severity counts are derived from imported
events, not a fixed success response. They are not live project health.

## Public aggregate artifact

The [free browser preview](https://hamedonassar95.github.io/Devobs/assets/free-devobs/)
links a downloadable `integration-acceptance.json`. It is generated by the actual
command above, with `scope:offline_synthetic_namespaces_only`,
`production_ready:false` and `live_integrations_verified:false`.
It includes only namespace names, bounded counts, synthetic CI conclusions and
stage counts. Raw events, commit hashes, fingerprints, annotations, values,
organization IDs, URLs and temporary paths are absent.

To regenerate the checked-in artifact, run the command and then its test:

```sh
node scripts/portfolio_integration_acceptance.mjs > assets/free-devobs/integration-acceptance.json
node --test tests/portfolio_integration_acceptance.test.mjs
```

The test compares the published JSON with a fresh real run, changes a valid CI
outcome to catch fabricated counters, rejects missing/duplicate namespace
coverage, and checks cleanup after both success and a later project-scope error.
Existing Node CI runs it, including artifact-only edits. Shared site checks
verify HTTP delivery; Docker copies the exact public JSON and its smoke test
compares served bytes with the reviewed file. Older free-profile release
candidates without this optional report retain their existing staging behavior.

Public synthetic examples can be shared; real monitoring data still requires
source/destination ownership and privacy review. No other repository, identity,
cloud resource, billing setting, secret or schedule is modified. P01 remains
**BLOCKED/NO-GO**, AI-9 **BLOCKED**, Codex runtime **OPEN**.
Rollback is a code revert; no cloud rollback is needed.
