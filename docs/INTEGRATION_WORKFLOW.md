# سير عمل تكاملات Devobs

تاريخ المراجعة: 2026-10-10، بتوقيت عمّان.
الحالة: خطة تشغيل موثّقة؛ لا يوجد في هذا التغيير ربط آلي بين التطبيقات أو تشغيل مجدول.

## الهدف والنطاق

تطوير خدمة أتمتة للشركات تبدأ بطلب محدد، ثم تتحقق من المصدر، وتنفذ تكاملًا صغيرًا، وتختبره، وتقدم نتيجة قابلة للمراجعة.
مستودع Devobs هو مرجع الكود وإعداداته. يمكن استخدام Notion لمتابعة الطلبات بعد تحديد المساحة المقصودة. مشروعات العملاء تبقى منفصلة عن مستودع الخدمة.

## حالة التحقق

- دُمج دليل الوجهات [PR #93](https://github.com/hamedonassar95/Devobs/pull/93)، وهو توثيق وليس تفعيلًا.
- WPVibe: استدعاء قائمة المواقع لم يُرجع مواقع مسجلة.
- Remote Desktop Commander: استدعاء قائمة الأجهزة لم يُرجع أجهزة متصلة.
- Notion: بحث Devobs في الاتصالين المتاحين لم يُرجع نتائج؛ لا يثبت ذلك عدم وجود المشروع باسم آخر أو خارج صلاحيات الاتصال. يلزم تحديد صفحة الوجهة قبل الكتابة.
- invideo: أدوات إنشاء الفيديو متاحة في الجلسة؛ لم يُنشأ مشروع أو فيديو ولم يتم اختبار توليد.
- Product Design: تتوفر مهارات استكشاف تجربة المنتج والنماذج؛ لم يبدأ تصميم واجهة.
- Codex Material Themes: مخصص لمظهر بيئة Codex، وليس موصل بيانات أو تصميمًا تلقائيًا لموقع Devobs.
- Codex Dev Workflows: استُخدمت مهارة استئناف العمل للتحقق من حالة طلب الدمج قبل متابعة الإضافة.
- مزوّد عرض مصادر البيانات الستين لم يُحدد؛ البحث العام لم يثبت هويته.

| المرحلة | الأداة أو الجهة | المخرج | شرط الانتقال |

| 2. التحقق من المصدر | البحث والوثائق الرسمية | رابط المزود، طريقة الاتصال، حدود الاستخدام | أدلة رسمية تخص التكامل المطلوب |

| 4. التنفيذ | GitHub مع Codex Dev Workflows | تغيير محدود في فرع مستقل | إعدادات اتصال معروفة وأسرار خارج الكود |
| 5. الاختبار | اختبارات المستودع واختبار اتصال فعلي | سجل نتيجة، صحة حقول، معالجة فشل | نجاح الاختبار وعدم تكرار السجلات |

| 8. المتابعة | GitHub وNotion إن تم ربطه | حالة تشغيل ورابط الدليل وآخر نجاح | إظهار الفشل وعدم وصف تشغيل فاشل بأنه ناجح |

## الفروع الاختيارية

- WordPress: استخدام WPVibe فقط عندما يكون موقع WordPress هو الوجهة المحددة. يلزم رابط الموقع وإتمام الاتصال، ثم معاينة التعديلات قبل نشرها.
- Windows: استخدام Remote Desktop Commander إذا كان التنفيذ يحتاج جهاز المستخدم. يلزم جهاز متصل وتحديد مسار المشروع؛ لا تُعدّل إعدادات الجهاز بمجرد إضافة اسم الأداة.
- الفيديو: استخدام invideo عند وجود مخرج فيديو مطلوب وسيناريو محدد. مثال مستقبلي: شرح الخدمة خلال 30 ثانية. لا تُعرض تكاملات غير مفعلة على أنها متاحة للعملاء.
- مظهر المحرر: Codex Material Themes اختيار شخصي منفصل عن التنفيذ والنشر.
- Gemini: لا تُضاف إعدادات افتراضية؛ يجب تحديد هل المقصود Gemini CLI أم API أم وجهة ضمن خدمة المزود.

## عقد الطلب المقترح

| الحقل | المحتوى |
| --- | --- |
| request_id | معرّف ثابت لمنع تكرار التنفيذ |
| project | Devobs أو معرّف مشروع العميل المستقل |
| objective | نتيجة واحدة قابلة للتحقق |
| source / destination | المصدر والوجهة الفعليان |
| status | مسودة / يحتاج إعدادًا / جاهز / قيد التنفيذ / فشل / مكتمل |
| evidence_url | رابط اختبار أو طلب دمج أو نتيجة فعلية |
| last_success_at | وقت آخر نجاح، ويترك فارغًا قبل أول نجاح |
| blocker | المعلومة أو صلاحية الاتصال الناقصة |

لا تُحفظ بيانات العملاء أو مفاتيح الاتصال في هذا المستودع العام.
عند بناء الربط لاحقًا، يُستخدم request_id لمنع إنشاء نسخ مكررة، وتكون إعادة المحاولة محدودة للأخطاء المؤقتة، ويُسجل الفشل بوضوح.

## التنفيذ الأول المطلوب

1. الحصول على رابط مزوّد العرض الأصلي.
2. التحقق من وثائقه واختيار مصدر واحد ووجهة واحدة من [الدليل](DATA_INTEGRATIONS.md).
3. تنفيذ تجربة اتصال وقراءة عينة محدودة، ثم فحص صحة النتائج.
4. إضافة الأتمتة المستمرة بعد نجاح التجربة وتحديد وتيرة التشغيل.

## ما أُنجز في هذه الإضافة

فحص نقاط الاتصال وحالة PR #93، وصياغة سير العمل وشروط القبول.
لم تُنشأ صفحات Notion أو فيديوهات أو مواقع أو اتصالات بيانات، ولم يتغير كود التشغيل.
