# المتطلبات وفهم المشكلة

## المشكلة

يحتوي Devobs على وحدات CI قابلة لإعادة الاستخدام وتوثيق تشغيل، لكن المساهمين يحتاجون إلى طريقة موحدة لاستخدام وكلاء البرمجة ومراجعة التغييرات عبر مراحل العمل.

## الأهداف

- توفير إعداد مشروع واحد لـCodex وClaude Code.
- توثيق مراحل المتطلبات والتصميم والتخطيط والتنفيذ والاختبار والنشر والمراقبة.
- توفير مهارات سير العمل ذات الصلة داخل المستودع بنسخ محلية قابلة للنقل بين أجهزة الفريق.
- حفظ نسبة المصدر ورخصة Apache 2.0 لمهارات AI DevKit المنسوخة.
- إبقاء إعداد الوكلاء منفصلًا عن CI/CD ونشر الموقع وأسرار التشغيل.

## خارج النطاق

- تشغيل الوكلاء أو استدعاء نماذج AI تلقائيًا في GitHub Actions.
- تنفيذ أو نشر تغييرات برمجية دون مراجعة بشرية.
- إضافة تكاملات رسائل أو إعداد بيانات اعتماد خارجية.

## معايير القبول

- يحدد `.ai-devkit.json` البيئتين ومراحل دورة العمل والمهارات المطلوبة.
- تكون ملفات المهارات نسخًا داخل المستودع، بلا روابط إلى مجلدات مستخدم محلية.
- ينجح فحص AI DevKit الأساسي وفحص هذه الميزة.
- يشرح دليل المساهم طريقة التحقق والتحديث وحدود الإعداد بوضوح.
