# Testing strategy

## Coverage goals

Test every catalog mapping and each validation boundary changed by the feature. Use synthetic metadata and generated local Ed25519 keys only. Existing adviser, correlation, bundle, and signed approval suites remain regression coverage. No live incidents, services, AI calls, or database fixtures are needed.

## Unit tests

- [x] Each supported category accepts its existing catalog runbook ID.
- [x] A known ID from a different category is rejected by `IncidentRecord` construction.
- [x] An unknown but syntactically valid runbook ID is rejected.
- [x] Serialized records reject a category/ID mismatch after the content digest is recomputed.
- [x] A trusted curator's correctly re-signed mismatched record is rejected before memory is returned and does not consume the approval ID.
- [x] The adviser preserves the current ID and test instruction for each supported category using the shared catalog.

## Integration and regression tests

- [x] A valid signed memory still contributes its current category runbook to a finding with provenance.
- [x] A rejected signed memory batch does not contribute a finding or consume its approval ID.
- [x] Existing bundle round-trip and deterministic digests remain unchanged for valid rows.
- [x] Existing malformed finding, tenant-scope, freshness, and replay-guard tests remain green.

## Test data and commands

All records are synthetic. Signature tests use in-memory Ed25519 keys generated by the test fixture. Targeted commands:

```bash
python3 -m unittest discover -s tests -p 'test_intelligence_context_graph.py' -v
python3 -m unittest discover -s tests -p 'test_intelligence_incident_memory_approval.py' -v
python3 -m unittest discover -s tests -p 'test_intelligence_adviser.py' -v
```

Run the repository's full Python suite after focused tests. Do not add network, model, deployment, or production-runtime testing for this offline catalog change.
